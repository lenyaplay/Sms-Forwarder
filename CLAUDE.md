# CLAUDE.md

Инструкции для Claude Code в этом репозитории. Здесь — только правила и ссылки, не содержание: единый источник истины для каждой темы — один документ в `docs/`, этот файл на него ссылается, а не пересказывает.

## Документационный инвариант

Не дублировать контент между `.md`-файлами. Если факт/правило уже описан в другом документе — ссылка на него, а не копия и не пересказ своими словами. Расхождение из-за дублирования обнаруживается позже, чем расхождение из-за отсутствия информации — поэтому при любом сомнении: искать существующий источник, а не заводить новый.

Исключение — когда явно нужен другой источник истины (например, разные версии для разных окружений); в этом случае явно указывается, почему.

## Обязательное чтение перед работой

- [README.md](README.md) — что за проект, компоненты, быстрый старт.
- [docs/Architecture.md](docs/Architecture.md) — устройство системы, модель токенов, модель данных.
- [docs/Development.md](docs/Development.md) — процесс разработки: спецификация прежде кода, обязательные автотесты, **обязательное использование скилов** (`stakeholder-requirements-gathering`, `query-validation`, `peer-review-template`, `analysis-qa-checklist`) на каждом шаге фичи, структура backend-кода, формат ошибок API.
- [docs/Roadmap.md](docs/Roadmap.md) — статус этапов, что уже сделано.
- `docs/specs/NNNN-*.md` — спецификация конкретной фичи (перед тем как трогать код этой фичи).

## Ключевое правило

Спецификация — прежде кода, автотесты — в рамках той же работы, что и сама фича, использование скилов разработки — обязательно на каждом шаге. Детали всех трёх правил — в [docs/Development.md](docs/Development.md), не повторяются здесь.
