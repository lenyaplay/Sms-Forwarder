# 0038 — action-кнопки "скопировать код" в уведомлении о новом SMS

## Контекст

Milestone 30 ([Roadmap 3.md](../roadmaps/Roadmap%203.md)). Владелец продукта (2026-09-06) хочет: если во входящем SMS есть OTP-код(ы), уведомление должно предлагать быстрое копирование кода без открытия приложения — 1 код → кнопка "Скопировать код", 2 кода → "Скопировать код 1"/"Скопировать код 2".

Требования собраны через `stakeholder-requirements-gathering` (2026-09-06, ответы владельца продукта).

## Текущее состояние

- Детектор кодов уже существует: `ui/thread/MessageTextSegmentation.kt` — `otpRegex = Regex("""\b\d{4,6}\b|\b\d{1,3}-\d{1,3}\b""")` (спека 0031: любое такое число трактуется как OTP, без эвристики по контекстным словам), `segmentMessageText(text: String): List<TextSegment>` — чистая Kotlin-функция без Android/Compose зависимостей, пригодна для переиспользования вне UI-потока (сервис/ресивер).
- Уведомления о входящем SMS строятся в `sms/IncomingSmsNotifier.kt`, `notifyIncoming(sender: String, text: String)` — `NotificationCompat.Builder` с `BigTextStyle`, единственным `contentIntent` (открыть тред). Кнопок-действий (`NotificationCompat.Action`) сейчас нет вообще. Каждое SMS — отдельное уведомление с уникальным ID (`AtomicInteger`), группировки (`MessagingStyle`/`setGroup`) нет.

## Требования (из интервью)

1. Извлечение кодов для уведомления переиспользует существующий `otpRegex`/`segmentMessageText` (та же логика, что подсвечивает коды в `ThreadScreen`) — не отдельная копия регулярки.
2. 1 найденный код → одна `NotificationCompat.Action` "Скопировать код". 2 найденных кода → две кнопки "Скопировать код 1"/"Скопировать код 2" (в порядке появления в тексте).
3. Более 2 кодов в тексте → показываются кнопки только для первых двух (по порядку появления), остальные игнорируются — не показывать все и не отказываться от кнопок совсем.
4. 0 кодов → уведомление без изменений (текущее поведение, без кнопок).
5. Нажатие кнопки копирует соответствующий код в `ClipboardManager` и показывает `Toast` "Код скопирован" — само уведомление не закрывается и не меняет текст, остаётся доступным (на случай второго кода/повторного просмотра).
6. Применимо только к текущей форме уведомления (одно SMS = одно уведомление) — групповые/суммарные уведомления не задействованы, так как их не существует в проекте.

## Допущения

- Допущение 1: лимит Android на число action-кнопок в уведомлении — практически 3 (платформенное ограничение, не настраиваемое); с максимум 2 OTP-кнопками запас есть даже если в будущем добавится ещё одно действие (например, Reply).
- Допущение 2: если оба найденных кода после `.filter { it.isDigit() }` (как в `TextSegment.Otp.code`) совпадают текстуально (дублирующееся число в сообщении встретилось дважды) — обе кнопки всё равно показываются с одинаковым текстом действия и одинаковым результатом копирования; отдельная дедупликация не требуется, так как это редкий и безвредный случай (уточняется как допущение, а не отдельное требование, поскольку не поднималось в интервью).

## Архитектура

- В `IncomingSmsNotifier.notifyIncoming(sender, text)`: вызвать `segmentMessageText(text).filterIsInstance<TextSegment.Otp>().take(2)`, получить 0-2 кода.
- Для каждого найденного кода добавить `NotificationCompat.Action` через `.addAction(...)` с `PendingIntent.getBroadcast(...)`, указывающим на новый `BroadcastReceiver` (например, `CopyOtpCodeReceiver`), получающий код через `Intent` extra.
- `CopyOtpCodeReceiver.onReceive`: положить код в `ClipboardManager.setPrimaryClip(...)`, показать `Toast.makeText(context, "Код скопирован", Toast.LENGTH_SHORT).show()`. Не вызывать `NotificationManager.cancel(...)` — уведомление остаётся.
- Регистрация ресивера — в `AndroidManifest.xml` (или динамически, если проект уже использует такой паттерн для похожих ресиверов — проверить на реализации).

## Критерии приёмки

- SMS с одним кодом (например, "Ваш код: 4821") → уведомление получает 1 action-кнопку "Скопировать код"; нажатие копирует "4821" в буфер обмена и показывает тост.
- SMS с двумя кодами → две кнопки "Скопировать код 1"/"Скопировать код 2", каждая копирует свой код независимо.
- SMS с тремя и более кодами → только первые два по порядку появления получают кнопки.
- SMS без кодов → уведомление как раньше, без кнопок, без регрессии по остальному поведению (`contentIntent`, `BigTextStyle` и т.д.).
- После нажатия кнопки уведомление не исчезает и не меняет вид (кроме, возможно, платформенного визуального отклика на клик — не задача этой спеки).

## Тесты

- Unit-тест на выбор кнопок по количеству кодов (0/1/2/3+) — можно тестировать логику извлечения (`segmentMessageText(...).filterIsInstance<TextSegment.Otp>().take(2)`) отдельно от `NotificationCompat`, без Android-зависимостей.
- Robolectric/инструментированный тест на `IncomingSmsNotifier`: проверка количества и текста `NotificationCompat.Action` на построенном `Notification` для текстов с 0/1/2/3 кодами.
- Тест/проверка `CopyOtpCodeReceiver`: получает intent с кодом → буфер обмена содержит этот код (через `ClipboardManager` в тестовом контексте).
- Регрессия: существующий тест(ы) на `IncomingSmsNotifier` (если есть) остаются зелёными для SMS без кодов.

## Результаты

Реализовано 2026-09-06.

- Новый `sms/CopyOtpCodeReceiver.kt` — обычный `BroadcastReceiver` (без Hilt, DI не нужен), копирует код из intent-extra в `ClipboardManager`, показывает тост "Код скопирован", уведомление не закрывает. Зарегистрирован в `AndroidManifest.xml` с `android:exported="false"`.
- `IncomingSmsNotifier.notifyIncoming` переиспользует существующий `segmentMessageText`/`TextSegment.Otp` (тот же детектор, что подсвечивает коды в `ThreadScreen`) — `take(2)` по порядку появления, 1 код → кнопка "Скопировать код", 2 → "Скопировать код 1"/"Скопировать код 2", 3+ — только первые два.
- **Баг, найденный `peer-review-template` до коммита** (см. `docs/Metrics.md` #7): изначальный `requestCode` у `PendingIntent.getBroadcast` был `sender.hashCode()*31+index` — два OTP-сообщения от одного отправителя подряд получали одинаковый `requestCode`, и `FLAG_UPDATE_CURRENT` тихо подменял код в кнопке ещё видимого первого уведомления на код второго. Исправлено: `requestCode = notificationId*2+index`, где `notificationId` — уникальный id самого вызова `notifyIncoming` (тот же id, что передаётся в `NotificationManager.notify`) — инъективность по построению (диапазоны `[2N, 2N+1]` для разных `N` не пересекаются).
- Новые Robolectric unit-тесты (JVM, без реального устройства): `IncomingSmsNotifierTest.kt` (5 тестов — 0/1/2/3+ кодов плюс регрессионный тест на баг выше) и `CopyOtpCodeReceiverTest.kt` (1 тест на копирование в буфер). Все зелёные, полный `:app:testDebugUnitTest` без регрессий.
- `peer-review-template` (повторно после фикса) подтвердил закрытие найденного бага без новых рисков коллизий. `analysis-qa-checklist` пройден.
- Приложение установлено на TECNO LI9 (`:app:installDebug`) для последующей ручной живой проверки владельцем продукта — реальный входящий SMS с OTP-кодом.
