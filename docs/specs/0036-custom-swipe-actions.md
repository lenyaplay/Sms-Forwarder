# 0036 — кастомный swipe-жест с открывающимися кнопками действий

## Контекст

Milestone 30, п.1 ([Roadmap 3.md](../roadmaps/Roadmap%203.md)). Найдено 2026-09-05 при ревью теста: порог `positionalThreshold` (0.75 в `FilterRuleRow`, 0.85 в `ConversationRow`) нигде не покрыт тестом на сам жест (`performTouchInput swipeLeft`), только non-gesture эквивалент (см. [Metrics.md](../Metrics.md)). При обсуждении с владельцем продукта выяснилось, что заодно нужен новый паттерн взаимодействия — не dismiss-свайп (действие сразу по завершении свайпа), а reveal-свайп с закрепляющимися кнопками действий (как в iOS Mail/Gmail), с более явным контролем через параметр угла отклонения.

Требования собраны через `stakeholder-requirements-gathering` (2026-09-06, ответы владельца продукта).

## Требования (из интервью)

1. **Параметры жеста**: только угол отклонения от горизонтали (доп. к позиционному порогу) — velocity/скорость флика не нужна.
2. **Охват**: заменяется сразу в обоих местах — `ConversationRow` (`ConversationsScreen.kt`) и `FilterRuleRow` (`FilterRulesScreen.kt`).
3. **Направление**: только свайп **влево** имеет значение (текущее различие StartToEnd=архивировать/EndToStart=удалить по направлению — упраздняется).
4. **Новый паттерн — reveal, не dismiss**:
   - Свайп влево, если пройден порог (позиция + угол) → строка сдвигается и открывает **круглые кнопки** в освободившемся пространстве справа:
     - `ConversationRow`: 2 кнопки — архивировать, удалить.
     - `FilterRuleRow`: 1 кнопка — удалить (у правил фильтра нет архивации).
   - Если порог **не** пройден → анимация возврата в закрытое состояние (как раньше).
   - Действие выполняется **тапом по кнопке**, не автоматически по завершении свайпа.
5. **Свайп дальше влево из открытого состояния**: ничего не происходит, строка остаётся в открытом положении с видимыми кнопками (никакого дополнительного действия за порогом).
6. **Свайп вправо из открытого состояния**: должен иметь свой порог закрытия — если порог пройден, строка закрывается (кнопки прячутся); если нет — пружинит обратно в открытое состояние (не в закрытое).
7. **Non-gesture эквивалент не меняется**: `ConversationRow` сохраняет long-press → `DropdownMenu` (архивировать/удалить), `FilterRuleRow` сохраняет отдельную `IconButton` для удаления — оба остаются единственным путём для TalkBack, так как кастомный жест не даёт встроенного a11y action.

## Допущения

- Допущение 1: конкретные числовые пороги (открытие/закрытие, угол в градусах) подбираются по аналогии с текущими (0.75/0.85 от ширины) и уточняются в процессе `query-validation`/реализации — если после ручной проверки на устройстве значения ощущаются неверно, это правится в рамках той же работы, не требует новой итерации требований.
- Допущение 2: ширина открытого состояния (сколько места отводится под круглые кнопки) — фиксированная, определяется размером и отступами самих кнопок (по аналогии с `AVATAR_SIZE`-паттерном в `ContactAvatar.kt`), не отдельный вычисляемый параметр.
- Допущение 3: угол считается по всему треку жеста от начальной точки касания до текущей позиции (не по последним N мс) — простейшая интерпретация, годная для одиночного прямого свайпа, которым это действие и является.
- Допущение 4: открытие одной строки не закрывает автоматически ранее открытую строку в списке (нет "только одна строка открыта одновременно" координации) — не запрошено владельцем продукта явно; если это окажется нужным, потребует отдельного решения (список должен знать об открытой строке).

## Архитектура

- Новый общий compose-модуль `ui/common/SwipeActionsRow.kt` (переиспользуется `ConversationRow` и `FilterRuleRow`, аналогично тому, как `ConfirmDialog`/`ContactAvatar` уже переиспользуются) — инкапсулирует:
  - Состояние: `Closed` / `Revealed` (2 состояния, `remember { mutableStateOf(...) }` + `Animatable` для позиции смещения).
  - `pointerInput` + `detectHorizontalDragGestures` (или `awaitEachGesture`, если нужен точный контроль над углом — угол требует и вертикальную дельту, значит `detectDragGestures`, не `detectHorizontalDragGestures`).
  - Конфигурируемые параметры: `revealThreshold: Float` (доля ширины), `closeThreshold: Float` (доля ширины открытого состояния), `maxAngleDegrees: Float` (макс. отклонение от горизонтали, за пределами которого жест не засчитывается — трактуется как вертикальный скролл/шум).
  - Content slot для основного содержимого строки + slot для списка круглых кнопок действий (`List<SwipeAction>` — иконка, contentDescription, onClick, цвет фона).
- `ConversationRow` передаёт 2 `SwipeAction` (архив/удалить), `FilterRuleRow` — 1 (удалить).
- Удаляется зависимость от `SwipeToDismissBox`/`rememberSwipeToDismissBoxState`/`SwipeToDismissBoxValue` (Material3) в обоих файлах.

## Критерии приёмки

- Свайп влево с недостаточной позицией/углом → строка возвращается в закрытое состояние (анимация).
- Свайп влево, порог пройден → появляются круглые кнопки (1 в FilterRules, 2 в Conversations), строка остаётся в открытом положении.
- Дальнейший свайп влево из открытого состояния → без изменений (не двигается дальше).
- Тап по каждой кнопке → соответствующее действие вызывается (`onArchiveToggle`/`onDeleteRequested` для Conversations, `onDeleteRequested` для FilterRules).
- Свайп вправо из открытого состояния, порог пройден → закрывается.
- Свайп вправо из открытого состояния, порог не пройден → остаётся открытым (пружинит назад в Revealed, не в Closed).
- Long-press меню (Conversations) и delete-кнопка (FilterRules) продолжают работать без изменений.
- Существующие Roborazzi-снапшоты (`ConversationsScreenSnapshotTest`, `FilterRulesScreenSnapshotTest`) не меняются визуально в состоянии покоя (Closed) — своей кнопки не показывают.

## Тесты

Новые (закрывают пробел, найденный в Metrics.md):
- `performTouchInput { swipeLeft() }` при позиции/угле выше порога → кнопки становятся видимыми (проверка через semantics/testTag на кнопках).
- Свайп на недостаточное расстояние → кнопки не появляются, строка на исходной позиции.
- Свайп под избыточным углом (почти вертикальный) при достаточном расстоянии по X → не засчитывается (проверка допущения 3 про угол).
- Тап по кнопке после открытия → вызывается правильный callback (mock/spy лямбда).
- Свайп вправо из открытого состояния, порог/не порог → корректное закрытие/возврат.
- Существующие Roborazzi-тесты остаются зелёными без изменений baseline.

## Результаты

Реализовано 2026-09-06.

- Новый компонент `ui/common/SwipeActionsRow.kt` — `Animatable`-based drag-жест (`awaitEachGesture`/`drag`), угол считается по совокупному смещению от точки касания, ширина открытого состояния — фиксированная константа (48dp кнопка + 8dp отступ на действие). Заменяет Material3 `SwipeToDismissBox` в `ConversationRow` (2 действия: архив/удалить) и `FilterRuleRow` (1 действие: удалить).
- Кнопки действий теперь эмитятся в композицию только пока `offsetX` показывает реальный "выезд" (`< -0.5px`), а не постоянно с `invisibleToUser()` — первая версия с `invisibleToUser()` не сработала, потому что `assertIsDisplayed()`/`performClick()` в Compose UI test идут через семантическое дерево на основе геометрии layout, а не реальный hit-test с учётом z-order; это обнаружил именно новый жестовый тест на реальном устройстве, а не ревью кода. Задокументировано в `Metrics.md`.
- Новый инструментированный тест `ui/common/SwipeActionsRowTest.kt` (6 тестов: ниже порога, выше порога, чрезмерный угол, тап по кнопке, свайп вправо ниже/выше порога закрытия) — все зелёные на реальном устройстве (TECNO LI9).
- Регрессионный прогон существующих `ConversationsScreenTest`/`FilterRulesScreenTest` (25 тестов) — все зелёные, включая тест, использовавший `useUnmergedTree` из-за старого `SwipeToDismissBox`-мерджинга семантики.
- Существующие Roborazzi-снапшоты (`ConversationsScreenSnapshotTest`, `FilterRulesScreenSnapshotTest`) не изменились — closed-состояние выглядит идентично.
- `peer-review-template`: один plausible-риск (конкурентные `scope.launch { offsetX.snapTo/animateTo }` по каждому drag-событию) — не переписывался кодом, так как `Animatable` сериализует конкурентные вызовы через внутренний mutex в порядке запуска; вместо рефакторинга добавлен поясняющий комментарий в коде.
- Non-gesture пути (long-press меню в Conversations, отдельная Delete-кнопка в FilterRules) не изменены — остаются единственным a11y-путём, как того требовала спека.

**Донастройка после живой проверки на устройстве (2026-09-06, тот же день)** — по Допущению 1 (числовые пороги подбираются по ощущениям в рамках той же работы, без новой итерации требований):
- Отступ справа у открытых кнопок увеличен с 8dp до 12dp дополнительно (итого 12dp вместо прежних 8dp) — владелец продукта отметил, что кнопки казались слишком прижаты к краю.
- `closeThreshold` поднят с 0.5 (50%) до 0.75 (75%) — автозакрытие открытой строки обратным свайпом теперь требует более уверенного жеста, чтобы не закрывалось слишком легко.
- 6 жестовых тестов перепрогнаны после изменения — все по-прежнему зелёные (тесты используют запасом большие смещения, не завязаны на точные пороговые значения).
