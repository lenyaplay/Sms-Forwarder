## Business Question

Владелец продукта поручил (2026-09-04) взять из бэклога Milestone 26 (см. [Roadmap 2.md](../roadmaps/Roadmap%202.md)) первые три пункта, оставшиеся после части 1 (визуальный полишинг, спека 0028): SIM-индикатор у сообщения в треде, группировка подряд идущих сообщений одного отправителя по времени (как в Telegram), автоматическое скрытие клавиатуры при скролле списка сообщений вверх.

Явно НЕ в этой итерации (остаются в Milestone 26 backlog): подсветка совпадений в поиске, распознавание ссылок/телефонов/OTP с контекстными меню, Telegram-style множественное выделение сообщений long-press.

## Decision This Informs

**Decision type:** Tactical (три независимых UX-улучшения `ThreadScreen`, один из трёх — с доработкой данных).
**Decider:** Владелец продукта.
**Decision deadline:** нет жёсткого срока.
**What happens if this analysis isn't available:** пользователь не видит, с какой SIM пришло/отправлено сообщение (при двух активных SIM это важно для контекста); длинные переписки визуально не читаются как в привычных мессенджерах (лишние повторы отступа/шапки на каждое сообщение); клавиатура закрывает часть экрана при просмотре истории, если её не скрывать вручную.

## Success Criteria

1. **SIM-индикатор у сообщения** (`ThreadScreen`/`MessageBubble`) — рядом с сообщением видно, через какую SIM оно было получено/отправлено, если у устройства 2+ активных SIM (та же логика видимости, что уже определяет `uiState.showSimSelector` в спеке 0028). Индикатор показывается только для сообщений с известным `subscriptionId`; для более старых сообщений, импортированных до фикса чтения `Telephony.Sms.SUBSCRIPTION_ID` (см. Scope/Data), индикатор просто не показывается — не заявляем "SIM неизвестна" и не делаем ретроактивный повторный импорт.
   - Требует доработки данных: `SmsHistoryImporter.HISTORY_PROJECTION` должен читать `Telephony.Sms.SUBSCRIPTION_ID` и заполнять `subscriptionId`/`simSlot` при импорте истории — сейчас это поле заполняется только для сообщений, полученных напрямую через `SmsDeliverReceiver` (`SMS_DELIVER` extras).
2. **Группировка сообщений по времени** — подряд идущие сообщения одного отправителя/направления с разницей по времени **< 5 минут** визуально объединяются: без повторного отступа/шапки между ними (шапка/таймстамп — только у первого сообщения группы, либо по существующему паттерну `MessageBubble`). Разрыв ≥ 5 минут или смена отправителя/направления — новая группа с полным оформлением.
3. **Авто-скрытие клавиатуры при скролле** (`ThreadScreen`) — скролл списка сообщений вверх (в сторону более старых, в любую сторону от нижнего края) скрывает системную клавиатуру и снимает фокус с поля ввода, аналогично поведению большинства мессенджеров.
4. Реализация не меняет backend-API — работа клиентская, только `android_gateway/`.
5. Автотесты на каждый пункт (визуальные assertions где возможно — наличие/отсутствие SIM-индикатора по testTag, семантика группировки через структуру composables, скрытие клавиатуры через `ImeVisibility`/фокус-состояние в androidTest) — по стандартному правилу проекта (`docs/Development.md`).

## Scope

**In scope:**
- `SmsHistoryImporter.kt` (`HISTORY_PROJECTION` и логика импорта) — чтение `Telephony.Sms.SUBSCRIPTION_ID`, заполнение `subscriptionId`/`simSlot` для импортированной истории.
- `ThreadScreen.kt`/`MessageBubble` — отображение SIM-индикатора при известном `subscriptionId` и 2+ активных SIM; визуальная группировка подряд идущих сообщений по правилу "< 5 минут, тот же отправитель/направление"; обработка скролла списка вверх → скрытие клавиатуры/снятие фокуса.
- Возможная миграция БД, если для доступа к `subscriptionId` истории потребуется схема, отличная от текущей (уточняется на этапе реализации по факту существующей схемы `MessageEntity`).

**Out of scope:**
- Ретроактивный повторный импорт/пересканирование `content://sms` для простановки `subscriptionId` уже существующим сообщениям — решено не делать (см. Success Criteria п.1).
- Подсветка совпадений в поиске, распознавание ссылок/телефонов/OTP, Telegram-style множественное выделение — остаются в Milestone 26 backlog.
- Изменения backend-API.

## Assumptions and Constraints

- SIM-индикатор не ретроактивен — только новые сообщения после фикса импорта (решение владельца продукта, `AskUserQuestion`).
- Порог группировки сообщений — 5 минут, тот же отправитель/направление (решение владельца продукта).
- Скрытие клавиатуры — при скролле списка вверх в любую сторону от низа, не только при "значительном" скролле (решение владельца продукта).
- Работа клиентская, backend не трогается.
- Возможна необходимость миграции Room-схемы — уточняется на этапе написания спеки после чтения текущей схемы `MessageEntity`.
