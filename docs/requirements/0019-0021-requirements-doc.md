## Business Question

Как убрать три конкретных источника раздражения при повседневном использовании Android Gateway App: неверный/неудобный переход по тапу на уведомление о новом SMS, заметная задержка/скролл при открытии длинной переписки и при холодном старте приложения, и отсутствие быстрого способа сбросить настройки сервера доставки без риска случайно снести правила фильтрации?

## Success Criteria

1. Спека фиксирует три независимые фичи (переход из уведомлений + разворачиваемый текст уведомления; мгновенная навигация к нужному сообщению в треде без видимой прокрутки всей истории + ускорение холодного старта списка диалогов; кнопка сброса настроек доставки) — каждая со своими критериями приёмки и тестами.
2. Перед фиксацией критериев приёмки для холодного старта — подтверждена конкретная причина через анализ текущего кода (не предположение), это задокументировано в спеке.
3. Реализация не меняет формат backend-API ([0003-sms-webhook.md](../specs/0003-sms-webhook.md)) — все три фичи чисто клиентские.

## Scope

**In scope:**
- `PendingIntent` уведомления о новом SMS (`IncomingSmsNotifier.notifyIncoming`) открывает конкретный тред, не просто список диалогов.
- `NotificationCompat.BigTextStyle` для полного текста SMS в уведомлении.
- Открытие треда с большой историей — переход сразу к нужной позиции (последнее сообщение при обычном открытии, найденное сообщение при переходе из поиска) без видимой линейной прокрутки.
- Диагностика и устранение конкретной подтверждённой причины медленной загрузки списка диалогов при холодном старте.
- Кнопка «Сбросить настройки доставки» на экране «Доставка»: `serverUrl`, `uploadToken`, retry-настройки (`maxAttempts`/`baseIntervalSeconds`/`backoffPolicy`) до дефолтов, пауза форвардинга → `false`.

**Out of scope:**
- Правила фильтрации ([0015](../specs/0015-gateway-sms-filtering.md)) — кнопка сброса их не трогает.
- Milestone 18 (`0018-gateway-delete-contact-privacy-export.md`, Draft) — отдельная работа, не пересекается с этим набором фич.
- Любые изменения backend/Viewer App.
- Полноценная пагинация/виртуализация списка диалогов сверх того, что нужно для устранения найденной причины медленного старта (если причина не в этом — не реализуется превентивно).

## Assumptions and Constraints

- Три фичи архитектурно независимы — реализуются и тестируются как три отдельные спеки/милестоуна, по решению владельца продукта (см. Open Questions ниже).
- «Мгновенная навигация без скролла» распространяется на два входа: обычное открытие треда (к последнему сообщению) и переход к найденному сообщению из полнотекстового поиска ([0014](../specs/0014-gateway-search-archive-delete.md)) — сейчас поиск лишь показывает список результатов, перехода в тред с прокруткой к конкретному сообщению нет вообще, это тоже часть работы, не только ускорение уже существующей прокрутки.
- Причина медленного холодного старта списка диалогов зафиксирована в спеке по итогам анализа кода (см. Data Sources), а не отдельного профилирования на устройстве с профайлером — время в бюджете сессии; если после фикса живая проверка на устройстве покажет, что проблема не устранена полностью, это будет явно отражено как открытый вопрос, а не скрыто.
- Кнопка сброса — точный список полей подтверждён владельцем: `serverUrl`+`uploadToken` (всегда), retry-настройки (до дефолтов `10`/`30`/`EXPONENTIAL`), пауза форвардинга (→ `false`). Правила фильтрации не входят.
