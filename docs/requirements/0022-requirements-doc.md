## Business Question

После фикса нестабильных лямбд (Milestone 18) подлагивание скролла списка диалогов на живом устройстве сохранилось, а холодный старт заметно медленнее, чем у системного SMS-приложения. Нужны цифры вместо гипотез — постоянный (но не всегда включённый) инструментарий для измерения производительности экранов и фоновых процессов, конкретная подтверждённая причина оставшегося лага скролла с измеримым порогом «исправлено», и устранение видимого пустого состояния списка диалогов при холодном старте, когда данные уже физически есть в Room.

---

## Decision This Informs

**Decision type:** Operational (доработка существующего работающего продукта — `references/decision_maker_framework.md`).
**Decider:** Владелец продукта.
**Decision deadline:** нет жёсткого срока.
**What happens if this analysis isn't available:** Лаги скролла и медленный холодный старт остаются без диагностического инструментария — любая будущая правка производительности снова опирается на догадки, а не на цифры; экран диалогов продолжает мигать пустым состоянием на данных, которые уже есть локально.

## Success Criteria

1. Спека фиксирует on-demand систему измерения (Compose-рендеринг через `JankStats` + фоновые процессы через таймеры), точный способ включения и место записи метрик.
2. Baseline лагов скролла (55.56% janky-кадров, снят вручную `adb shell dumpsys gfxinfo`) сопоставлен с тем же замером на системном SMS-приложении на том же устройстве — порог «исправлено» для Milestone 21 выводится из этого сравнения, а не назначается произвольным числом.
3. Причина видимого пустого состояния при холодном старте подтверждена в коде (уже сделано в разведке этой сессии — `ConversationsUiState` не различает «Flow ещё не эмитил» и «эмитил пустой список»), и зафиксирован конкретный UX-фикс.
4. Отдельное исследование: как системное SMS-приложение показывает список мгновенно при своём холодном старте — сначала внешние замеры (`adb shell am start -W`, `dumpsys`, логи собственного приложения), и при необходимости — статический анализ APK системного приложения (`apktool`/`jadx`) исключительно для изучения применённых техник (interoperability/обучение), не для копирования или модификации чужого кода (см. Constraints).
5. Реализация не меняет формат backend-API — вся работа клиентская.

## Scope

**In scope:**
- Новая on-demand система измерения производительности: `androidx.metrics.performance` (JankStats) для Compose-экранов + таймеры вокруг фоновых операций (импорт истории, форвардинг). Включается единым переключателем в новом разделе «Диагностика» на экране «Настройки» (не отдельная точечная настройка — см. Open Questions/Assumptions), пишет в logcat и в файл в app-private storage.
- Измерение и сравнение (`dumpsys gfxinfo`) скролла списка диалогов Gateway App против системного SMS-приложения на одном устройстве (TECNO LI9) — вывод числового порога «исправлено» из этого сравнения.
- Диагностика и устранение конкретной подтверждённой причины лага скролла (кандидаты: `SwipeToDismissBox` на строку, тень `Card`, пересборка списка на каждую эмиссию `Flow` без `distinctUntilChanged`) — меняется только то, что подтверждено измерением до/после.
- Замер холодного старта системного приложения (`adb shell am start -W`, время до первого кадра) как ориентир, плюс собственные логи Gateway App для понимания его собственного пути до первой эмиссии `Flow`.
- Устранение пустого состояния списка диалогов до первой эмиссии `Flow`: явное разделение «ещё не грузили» и «загрузили, пусто» в `ConversationsUiState`, экран не показывает «Нет сообщений» в первом случае.
- Push-уведомление и связанный с ним холодный старт (пункт 4 исходного roadmap-списка) — покрывается тем же фиксом пустого состояния, отдельного кода не требует (см. разведка: запись в Room в `SmsDeliverReceiver` уже гарантированно предшествует показу уведомления).

**Out of scope:**
- Копирование, модификация или переиспользование кода/ресурсов системного SMS-приложения — статический анализ его APK (`apktool`/`jadx`) допустим и, при необходимости, проводится исключительно для изучения применённых техник (interoperability/обучение), результат — только текстовое описание техники в спеке, не заимствованный код.
- Полноценная пагинация/виртуализация списка диалогов сверх того, что подтверждено измерением как причина лага (см. прецедент 0019-0021: не реализуется превентивно).
- Постоянно включённый (always-on) оверлей производительности — инструментарий explicitly on-demand.
- Любые изменения backend/Viewer App.

## Assumptions and Constraints

- «Более общий пункт» (ответ владельца продукта на вопрос про переключатель) трактуется как: один переключатель в новом разделе «Диагностика» на экране «Настройки», управляющий разом и JankStats-замером экранов, и таймерами фоновых процессов — не отдельные переключатели на каждую метрику и не debug-only гейт без UI. Работает на любой сборке (не только debug), поскольку это осознанный пользовательский инструмент диагностики, а не dev-заглушка.
- Метрики пишутся и в logcat, и в файл в app-private storage (для сравнения before/after без риска потерять данные при закрытии logcat-сессии).
- Сравнение с системным SMS-приложением начинается с внешне наблюдаемых замеров (`dumpsys`, `am start -W`, собственные логи); статический анализ его APK (`apktool`/`jadx`) допускается как следующий шаг для изучения техник (не копирования кода) — владелец продукта явно подтвердил это как интероперабельность/обучение, а не заимствование стороннего кода.
- Холодный старт: до первой эмиссии `Flow` список диалогов показывает пустой экран без текста «Нет сообщений» (не спиннер) — решение исходит из уже прочитанного кода (никакого prewarm/splash сейчас нет) и из риска, что спиннер сам может мигать на быстрых устройствах; будет явно перепроверено на устройстве в рамках живой проверки, и если пустой экран без текста ощущается как регресс — это будет зафиксировано как открытый вопрос, не молча принято.
- Порог «лаги скролла исправлены» — не фиксируется числом заранее, выводится из сравнения с системным приложением в рамках реализации; финальное число фиксируется в самой спеке 0022 (Draft → Implemented), не в этом документе.
