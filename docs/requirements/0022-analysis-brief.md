## The Question

> Как получить цифры вместо гипотез про подлагивание скролла списка диалогов и медленный холодный старт, завести постоянный (но не всегда включённый) инструментарий измерения, и убрать пустой экран, который показывается на данных, уже существующих локально?

---

## What "Done" Looks Like

1. Спека `docs/specs/0022-gateway-performance-diagnostics.md` написана — on-demand инструментарий, подтверждённая причина лага скролла с числом-порогом, фикс пустого состояния при холодном старте, каждое — со своими критериями приёмки и планом тестов.
2. Порог «лаги скролла исправлены» выведен из реального сравнения с системным SMS-приложением на том же устройстве, а не назначен произвольно.
3. Исследование «как системное приложение показывает список мгновенно» задокументировано через внешние замеры (`am start -W`, `dumpsys`, собственные логи) и, при необходимости, статический анализ его APK (`apktool`/`jadx`) для изучения техник — без копирования/модификации чужого кода.
4. `docs/roadmaps/Roadmap 2.md` — Milestone 21 помечен выполненным с честной фиксацией итоговых цифр и отклонённых гипотез.

## Approach (high level)

1. Спека 0022, раздел A: `PerfMonitor` (`androidx.metrics.performance`/`JankStats` + таймеры фоновых операций), один переключатель в разделе «Диагностика» на `SettingsScreen`, логирование в logcat и файл app-private storage.
2. Спека 0022, раздел B: живой замер системного приложения (`dumpsys gfxinfo`, `am start -W`) как ориентир → фиксация числового порога в самой спеке → диагностика кандидатов (SwipeToDismissBox/тень/пересборка списка) по одному с замером до/после через новый `PerfMonitor`, оставить только подтверждённые фиксы.
3. Спека 0022, раздел C: `hasLoadedOnce` в `ConversationsUiState`/`ConversationsViewModel`, `ConversationsContent` не показывает «Нет сообщений» до первой эмиссии — пустой экран без текста вместо этого (см. requirements doc Open Questions #4, перепроверяется живой проверкой).
4. `query-validation` перед кодом (условия показа/скрытия пустого состояния, точный набор метрик), реализация, тесты в той же работе, `peer-review-template`, `analysis-qa-checklist`, статус спеки → `Implemented`, запись в `Roadmap 2.md`.

## Constraints and Risks

- Сравнение с системным SMS-приложением — другой технологический стек (не Compose), даёт числовой ориентир, не архитектурный рецепт; риск, что порог окажется недостижим в рамках Compose-архитектуры без более глубокого рефакторинга — если так, фиксируется как открытый вопрос в спеке, не занижается искусственно.
- `androidx.metrics.performance` — новая зависимость, нужно проверить совместимость с `compileSdk 34`/`minSdk 26` перед добавлением.
- Пустой экран без текста при холодном старте — предположение аналитика, требует живой проверки на устройстве до фиксации как окончательного решения (см. requirements doc, Open Question #4).

## Not In Scope (explicitly)

- Копирование, модификация или переиспользование кода/ресурсов системного SMS-приложения (статический анализ APK для изучения техник — в scope, см. таблицу выше).
- Always-on оверлей производительности.
- Полная пагинация/виртуализация списка диалогов без измеримого обоснования.
- Backend/Viewer App.
