## Business Question

Milestone 26 (индикатор SIM, группировка сообщений) закрыт в частях 1 и 2 (specs 0028, 0029). Владелец продукта поручил (2026-09-04) доделать оставшиеся 3 пункта бэклога этого же Milestone одной спекой: (1) подсветка найденной подстроки в результатах поиска, (2) распознавание и подсветка ссылок/телефонов/OTP-кодов в тексте сообщения с контекстными действиями, (3) Telegram-style множественное выделение сообщений long-press с массовым удалением.

## Decision This Informs

**Decision type:** Tactical (три независимых UX-улучшения, завершают уже начатый Milestone).
**Decider:** Владелец продукта.
**Decision deadline:** нет.
**What happens if this analysis isn't available:** пользователь не видит, что именно совпало в результатах поиска (текст просто выводится целиком); ссылки/номера/коды в сообщениях нельзя быстро использовать (открыть, позвонить, скопировать) без ручного копирования всего текста; удаление нескольких сообщений требует по одному long-press+подтверждение на каждое.

## Success Criteria

1. **Подсветка поиска** — в `SearchResultsList` (`ConversationsScreen.kt`) найденная подстрока (`uiState.query`, регистронезависимо) визуально выделена (цвет/жирность) внутри `SearchResultUi.text`.
2. **Распознавание элементов текста** (`MessageBubble`, `ThreadScreen.kt`):
   - Ссылки (http/https, возможно www.-без-схемы) — подсвечены, тап открывает контекстное меню: открыть в браузере / скопировать.
   - Номера телефонов — подсвечены, тап открывает контекстное меню: позвонить / написать сообщение / скопировать.
   - Отдельно стоящее 4-6-значное число — распознаётся как OTP-код без дополнительной эвристики по контексту (решение владельца продукта: "любое отдельное 4-6-значное число — считать OTP", осознанный компромисс — короткие числа вроде времени/года в тексте будут ложно подсвечиваться, это принято, не в скоупе фикса). Тап по коду копирует его в буфер немедленно, без промежуточного меню/кнопки.
3. **Множественное выделение сообщений** (`ThreadScreen`):
   - Long-press по сообщению переводит его в выделенное состояние (не открывает меню "Удалить" напрямую, как сейчас) — исходный `TopAppBar` скрывается, показывается contextual TopBar со счётчиком выделенных, кнопкой "Удалить" (массово для всех выделенных) и крестиком снятия выделения (выход из режима).
   - В режиме выделения — обычный tap (не long-press) по другому сообщению добавляет/убирает его из выделения (решение владельца продукта: поддержка нескольких сообщений сразу, массовое удаление).
   - Повторный long-press по уже выделенному сообщению — не снимает выделение конкретно этим жестом отдельно оговорённым способом (снятие — через крестик TopBar или повторный тап по этому сообщению) — по образцу Telegram, обычное текстовое выделение слова остаётся доступно вне режима множественного выделения (когда список сообщений не в режиме selection).
4. Реализация не меняет backend-API — работа клиентская, только `android_gateway/`.
5. Автотесты на каждый пункт по стандартному правилу проекта.

## Scope

**In scope:**
- `ConversationsScreen.kt`/`SearchResultsList` — подсветка совпадения.
- `ThreadScreen.kt`/`MessageBubble` — распознавание ссылок/телефонов/OTP через `AnnotatedString`+`ClickableText` или `LinkAnnotation` (Compose), контекстные меню/действия (`Intent.ACTION_VIEW`, `Intent.ACTION_DIAL`/`ACTION_SENDTO`, `ClipboardManager`).
- `ThreadScreen.kt`/`ThreadViewModel` — режим множественного выделения: набор выделенных id сообщений в `ThreadUiState`, замена `TopAppBar` на contextual TopBar в режиме выделения, массовое удаление.

**Out of scope:**
- Изменения backend-API.
- Уточнение OTP-эвристики контекстными словами (осознанно отклонено владельцем продукта — см. Success Criteria п.2).
- Любые другие пункты Milestone (уже реализованы в 0028/0029) или Milestone 27/28.

## Assumptions and Constraints

- OTP-эвристика — любое отдельное 4-6-значное число, без учёта контекста (решение владельца продукта, осознанный компромисс с ложными срабатываниями).
- Множественное выделение — поддерживает несколько сообщений одновременно, массовое удаление (решение владельца продукта).
- Приоритет между тремя пунктами — равнозначный, реализация в удобном порядке (решение владельца продукта).
- Работа клиентская, backend не трогается.
