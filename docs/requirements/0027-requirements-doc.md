## Business Question

Владелец продукта (2026-09-03), сравнение экрана диалогов с системным SMS-приложением: «У смс приложения системного есть ещё знак профиля в круге слева от сообщения + у нас сейчас разные item при поиске и при начальном экране — при поиске должны быть те же самые. И пункт настройки надо переместить в TopBar рядом с архивными, а снизу убрать nav bar и по дефолту отображать сообщения + на строку поиска добавить крестик».

Четыре независимых UI-расхождения с системным приложением, зафиксированные одним запросом:
1. Нет круглого аватара контакта слева от строки диалога.
2. Строка результата поиска — визуально другой компонент, чем строка обычного диалога.
3. "Настройки" — таб нижней nav bar, а не иконка в TopBar; нижняя nav bar занимает экранное место постоянно ради одного редко используемого перехода.
4. Поле поиска не имеет кнопки очистки.

## Success Criteria

1. **Аватар** — круглое изображение слева от каждой строки диалога: фото контакта, если доступно; иначе первая буква `displayName`, если имя резолвится; иначе серая иконка-силуэт (в т.ч. для короткого буквенно-цифрового sender ID и при отсутствии `READ_CONTACTS` — единое правило, без отдельных кейсов).
2. **Единый вид строки** — результат поиска использует тот же визуальный компонент (аватар, шрифты, отступы, время), что обычная строка диалога; swipe-архивирование/удаление и long-press меню в поиске **не** переносятся — только внешний вид, поведение остаётся как у клика по результату конкретного сообщения.
3. **Settings в TopBar** — иконка настроек в `TopAppBar` экрана диалогов (рядом с архивным тогглом), нижняя `NavigationBar` убирается полностью; экран диалогов — безальтернативный дефолтный/единственный экран верхнего уровня. Delivery/FilterRules/DeliveryLog остаются достижимы только через сам экран Settings, как сейчас — меняется только точка входа в Settings.
4. **Очистка поиска** — кнопка "x" в поле поиска, видна только когда есть введённый текст, очищает поле по клику.
5. Реализация не меняет backend-API — работа клиентская, только `android_gateway/`.
6. Автотесты на каждый пункт — по стандартному правилу проекта (`docs/Development.md`).

## Scope

**In scope:**
- `ContactNameResolver` — резолвинг `photoUri` дополнительно к `displayName`, миграция формата persistent-кеша.
- Новый переиспользуемый composable для аватара (fallback-логика: фото → инициал → силуэт).
- Общий content-composable строки диалога, используемый и списком, и результатами поиска.
- `NavGraph.kt` — удаление нижней `NavigationBar`, `ConversationsScreen.kt` — иконка Settings в TopBar и кнопка очистки поиска.

**Out of scope:**
- Изменение самого экрана `SettingsScreen` (кнопки Delivery/FilterRules/DeliveryLog внутри него не трогаются).
- Одноразовая принудительная миграция уже закэшированных (Milestone 24) записей ради немедленного подтягивания фото — по решению владельца продукта не критично, т.к. приложение ещё не в production (см. Open Questions).
- Отдельный вид аватара для alphanumeric sender ID (банк/короткий код) — используется тот же силуэт-фолбэк, что и при отсутствии разрешения.
- Push-уведомления (FCM), поиск по тексту в Viewer App и прочий бэклог — не входят в этот Milestone, но подтверждено, что этот Milestone делается раньше них.

## Assumptions and Constraints

- Приложение ещё не в production — миграция уже существующего пользовательского кеша не требует принудительного форс-пересчёта, естественная инвалидация по `ContentObserver` достаточна.

- Единое правило фолбэка аватара (буква/силуэт) без специальных случаев для типа отправителя.
- Результаты поиска — только внешний вид, не полный функционал строки диалога.
