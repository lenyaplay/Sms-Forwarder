## The Question

Даёт ли буквальная реализация формул BM/EM/SYM статьи поверх точной geometry Compose-дерева более надёжную оценку визуального баланса, чем текущая пиксельная эвристика — и какой набор весов `ai` использовать по умолчанию?

---

## What "Done" Looks Like

1. Формулы (1)-(17) статьи реализованы над JSON-geometry (bounding box каждого visible SemanticsNode), не над пикселями.
2. Три реализации веса `ai` (равные / по площади / по типу элемента) — конфигурируемый параметр инструмента.
3. Сравнение всех трёх на 6 baseline PNG (Conversations/Thread/Settings × light/dark): таблица BM/EM/SYM-значений + PNG-визуализация центра масс и осей симметрии на скриншоте, для каждого набора весов.
4. Владелец продукта видит сравнение и явно выбирает дефолтный набор весов (или подтверждает "все три равноправны").

## Approach (high level)

1. Добавить в `*SnapshotTest.kt` экспорт geometry semantics-дерева (bounding box + минимальные атрибуты для классификации типа: text/contentDescription/clickable) в JSON рядом с PNG.
2. В `tools/ui-metrics/` реализовать точные формулы BM/EM/SYM над этим JSON, с параметром выбора весовой функции `ai` (equal / area / type-based).
3. Прогнать все 3 набора весов на всех 6 JSON+PNG пар — получить таблицу BM/EM/SYM.
4. Реализовать визуализацию (центр масс + оси симметрии, наложенные на PNG) для каждого набора весов на каждом экране.
5. Показать таблицу+визуализацию владельцу продукта, зафиксировать решение по весам в спеке.
6. Написать спеку `docs/specs/0034-...md` с формулами, весами, критериями приёмки, автотестами на формулы (синтетические/известные входы) — код писать только после отдельной явной команды.

## Constraints and Risks

- Классификация "по типу элемента" — не из статьи, отдельное допущение проекта; будет явно задокументирована в спеке, не выдаётся за часть оригинальной методологии.
- Экспорт всех visible nodes может дать шумный/избыточный список объектов (не только "значимые" визуальные элементы) — риск отражён в требованиях, но принят явным решением владельца продукта (объект = все visible nodes).
- Формат сравнения (таблица + визуализация) требует нового скрипта отрисовки поверх PNG — не покрывается существующим кодом.

- Автоматический выбор "правильного" набора весов без участия владельца продукта.
