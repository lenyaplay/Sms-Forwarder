## Milestone 30 — Android Gateway App: кастомный swipe-to-dismiss, раздельное вкл/выкл форвардинга по SIM, @Preview для всех компонентов, saliency heatmap

Статус: **Draft, не начата**. Собрано 2026-09-06 — первые два пункта перенесены из Backlog по решению владельца продукта, каждый требует отдельной спеки (новые требования к продукту, не техдолг); третий пункт не входил в требования спеки 0034 и остался открытым при закрытии Milestone 29 (архивирован в [Roadmap Archived 2.md](Roadmap%20Archived%202.md)); четвёртый добавлен владельцем продукта перед началом ручной работы над дизайном.

- [x] Кастомный swipe-жест взамен штатного `SwipeToDismissBox` — реализовано ([0036-custom-swipe-actions.md](../specs/0036-custom-swipe-actions.md)): reveal-жест с закрепляющимися круглыми кнопками (архив+удалить в `ConversationRow`, удалить в `FilterRuleRow`), угол+позиционные пороги, 6 новых инструментированных тестов на сам жест (закрывают пробел, найденный 2026-09-05 — порог 0.75/0.85 не был покрыт тестом на реальный `performTouchInput`, см. [Metrics.md](../Metrics.md) записи #6).
- [ ] Раздельное вкл/выкл форвардинга по SIM-слоту — сейчас единственный общий тумблер паузы форвардинга действует на всё приложение сразу (`GatewayConfigStore`, см. Milestone 19), независимо от того, с какой SIM пришло/уходит сообщение. Уточнено с владельцем продукта (2026-09-06): именно вкл/выкл пересылки по конкретной SIM, не разные server URL/token на SIM — существующие фильтры по `subscriptionId` (спека 0015) и SIM-лейбл у сообщения (спека 0029) не покрывают этот случай.
- [ ] **Saliency heatmap-визуализации как часть репозитория** — во время бейк-оффа saliency (Milestone 27, Stage C) для сравнения моделей был сгенерирован скрипт, рисующий тепловую карту поверх каждого скриншота (композит оригинал+heatmap); скрипт и картинки были одноразовыми и удалены после выбора модели (Допущение 9 спеки 0033). Нужно вынести генерацию heatmap в постоянный инструмент — не только числовой `saliency`-score в CLI, но и сохранённые PNG с картой внимания для каждого экрана/темы, коммитятся в репозиторий и перегенерируются вместе с остальными Stage C метриками при обновлении baseline-скриншотов.
- [x] **`@Preview` для всех Compose-компонентов** — реализовано ([0035-compose-previews.md](../specs/0035-compose-previews.md)): 7 экранов + 9 ключевых переиспользуемых компонентов (`ConversationRow`, `MessageBubble`, `DateSeparatorRow`, `FilterRuleRow`, `DeliveryLogRow`, `SimPicker`, `ConfirmDialog`, `ContactAvatar`, `NewMessageDialog`), по 2 `@Preview` каждый (light/dark) — 32 всего. Ручная визуальная проверка в Android Studio Preview pane за владельцем продукта.
