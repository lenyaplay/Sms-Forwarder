## Milestone 30 — Android Gateway App: кастомный swipe-to-dismiss, @Preview для всех компонентов, saliency heatmap

Статус: **Draft, не начата**. Собрано 2026-09-06 — первый пункт перенесён из Backlog по решению владельца продукта (требовал отдельной спеки — новые требования к продукту, не техдолг); второй пункт не входил в требования спеки 0034 и остался открытым при закрытии Milestone 29 (архивирован в [Roadmap Archived 2.md](Roadmap%20Archived%202.md)); третий добавлен владельцем продукта перед началом ручной работы над дизайном. Пункт "раздельное вкл/выкл форвардинга по SIM" убран 2026-09-06 — см. Backlog.

- [x] Кастомный swipe-жест взамен штатного `SwipeToDismissBox` — реализовано ([0036-custom-swipe-actions.md](../specs/0036-custom-swipe-actions.md)): reveal-жест с закрепляющимися круглыми кнопками (архив+удалить в `ConversationRow`, удалить в `FilterRuleRow`), угол+позиционные пороги, 6 новых инструментированных тестов на сам жест (закрывают пробел, найденный 2026-09-05 — порог 0.75/0.85 не был покрыт тестом на реальный `performTouchInput`, см. [Metrics.md](../Metrics.md) записи #6).
- [ ] **Saliency heatmap-визуализации как часть репозитория** — во время бейк-оффа saliency (Milestone 27, Stage C) для сравнения моделей был сгенерирован скрипт, рисующий тепловую карту поверх каждого скриншота (композит оригинал+heatmap); скрипт и картинки были одноразовыми и удалены после выбора модели (Допущение 9 спеки 0033). Нужно вынести генерацию heatmap в постоянный инструмент — не только числовой `saliency`-score в CLI, но и сохранённые PNG с картой внимания для каждого экрана/темы, коммитятся в репозиторий и перегенерируются вместе с остальными Stage C метриками при обновлении baseline-скриншотов.
- [x] Кнопка "назад" при активном мульти-выборе сообщений в `ThreadScreen` — реализовано ([0037-back-clears-selection.md](../specs/0037-back-clears-selection.md)): `BackHandler(enabled = isSelectionMode)` снимает выделение первым нажатием, второе нажатие — обычная навигация. Новый Hilt Activity-level инструментированный тест (второй в проекте после `DeliveryResetActivityTest`), регрессия не выявлена.
- [x] Action-кнопки "скопировать код" в уведомлении о новом SMS — реализовано ([0038-notification-otp-copy-actions.md](../specs/0038-notification-otp-copy-actions.md)): переиспользует существующий детектор OTP из `ThreadScreen`, 1 код → "Скопировать код", 2 → "Скопировать код 1"/"Скопировать код 2", 3+ — первые два. В процессе реализации `peer-review-template` нашёл и закрыл реальный баг с коллизией `PendingIntent.requestCode` между уведомлениями от одного отправителя (см. [Metrics.md](../Metrics.md) запись #7). Установлено на устройство для живой проверки.
- [ ] Архив как отдельный навигируемый экран — сейчас после перехода в архив нажатие "назад" выходит из приложения вместо возврата на первый экран (список входящих). Владелец продукта (2026-09-06): архив должен быть отдельным экраном с собственной навигацией (back stack), а не режимом отображения того же экрана без записи в стек. Требует отдельной спеки (новое требование к продукту, не техдолг) — уточнить текущую реализацию переключения в архивный вид (флаг `isArchivedView` в `ConversationsScreen`/`ConversationsContent`, судя по коду выше) и как это ляжет на `NavHost`/навигационный граф.
- [x] **`@Preview` для всех Compose-компонентов** — реализовано ([0035-compose-previews.md](../specs/0035-compose-previews.md)): 7 экранов + 9 ключевых переиспользуемых компонентов (`ConversationRow`, `MessageBubble`, `DateSeparatorRow`, `FilterRuleRow`, `DeliveryLogRow`, `SimPicker`, `ConfirmDialog`, `ContactAvatar`, `NewMessageDialog`), по 2 `@Preview` каждый (light/dark) — 32 всего. Ручная визуальная проверка в Android Studio Preview pane за владельцем продукта.
