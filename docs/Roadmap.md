# Roadmap

Дорожная карта разработки по этапам, от базовой инфраструктуры до MVP и дальнейших улучшений. Порядок последовательный — этапы без явных зависимостей от следующих можно частично распараллелить, но рекомендуется двигаться сверху вниз.

## Milestone 0 — Подготовка

- [x] Инициализация Go-модуля, структура проекта (`cmd/`, `internal/handlers`, `internal/services`, `internal/storage`)
- [x] Инициализация Android Viewer App проекта (Kotlin, минимальный шаблон)
- [x] Настройка SQLite и системы миграций (собственный минимальный мигратор на `embed.FS`, без cgo-зависимостей)

## Milestone 1 — Авторизация пользователей

- [x] Регистрация и логин по логину + паролю, хэширование паролей (bcrypt/argon2)
- [x] Выдача JWT access + refresh, эндпоинт обновления токена
- [x] Логаут и отзыв refresh-токена
- [x] Таблицы `users`, `refresh_tokens`

См. [спецификацию 0001-auth](specs/0001-auth.md).

## Milestone 2 — Устройства и токены

- [x] CRUD для `devices`: регистрация устройства-шлюза
- [x] Генерация, ревокация и перевыпуск `upload_token`
- [x] `viewer_bindings`: выдача и отзыв `download_token` для привязки просматривающих аккаунтов к устройству

См. [спецификацию 0002-devices-tokens](specs/0002-devices-tokens.md).

## Milestone 3 — Приём SMS (webhook)

- [x] Эндпоинт приёма webhook от Gateway App: валидация `upload_token`
- [x] Опциональная проверка подписи `X-Signature` (HMAC-SHA256)
- [x] Дедупликация повторных доставок (Gateway App повторяет отправку до 10 раз)
- [x] Сохранение сообщений в `messages`
- [x] Ручное end-to-end тестирование с реальным приложением-шлюзом на устройстве (2026-08-26, реальный SMS дошёл до Viewer App через Gateway App → webhook → бэкенд)

См. [спецификацию 0003-sms-webhook](specs/0003-sms-webhook.md).

## Milestone 4 — REST API для просмотра

- [x] Список устройств, доступных текущему пользователю (`GET /devices`, см. допущение 7 в [спецификации 0002](specs/0002-devices-tokens.md))
- [x] Список сообщений по устройству с пагинацией и фильтрацией

См. [спецификацию 0005-viewer-messages-api](specs/0005-viewer-messages-api.md).

## Milestone 5 — Realtime-доставка

- [x] WebSocket (или SSE) эндпоинт для push новых сообщений подписанным клиентам
- [x] Fallback на REST-поллинг при разрыве соединения (клиентское поведение поверх уже существующего `GET /devices/{id}/messages?since=`)

См. [спецификацию 0006-realtime-delivery](specs/0006-realtime-delivery.md).

## Milestone 6 — Android Viewer App (MVP)

- [x] Экран логина
- [x] Список привязанных устройств
- [x] Добавление устройства по `download_token` (ручной ввод / QR-код)
- [x] Лента сообщений с realtime-обновлением
- [x] Ручное end-to-end подтверждение на физическом устройстве: привязка по `download_token` и обновление ленты в реальном времени через SSE (2026-08-26)

См. [спецификацию 0007-android-viewer-mvp](specs/0007-android-viewer-mvp.md).

## Milestone 7 — Безопасность и эксплуатация

- [x] Rate-limiting на webhook-эндпоинт (и `/auth/*`)
- [x] HTTPS/TLS в деплое (пример nginx-конфига), Docker-контейнеризация бэкенда
- [x] Логирование и health-check эндпоинт

См. [спецификацию 0008-security-and-ops](specs/0008-security-and-ops.md).

## Milestone 9 — Многопользовательский онбординг и самообслуживание (Android)

- [x] Экран регистрации (открытая, без инвайт-кода)
- [x] Настраиваемый server URL (экран настройки сервера + экран настроек)
- [x] Генерация QR-приглашения (`download_token`) владельцем устройства
- [x] Базовый экран управления токенами устройства (список/отзыв `download_token`, перевыпуск `upload_token`)

См. [спецификацию 0010-android-onboarding-self-service](specs/0010-android-onboarding-self-service.md).

## Milestone 10 — Экран создания устройства, исправление разрешения камеры, тёмная тема (Android)

- [ ] Экран создания устройства (минтинг `upload_token`) — пересмотр решения спек 0007/0010, создание устройства теперь доступно из UI
- [ ] Исправление запроса разрешения на камеру на экране добавления устройства (кнопка сканирования QR видна всегда, разрешение запрашивается по нажатию)
- [ ] Исправление контраста тёмной темы (тёмный текст на тёмном фоне из-за отсутствия `Surface` в `SmsForwarderViewerTheme`)

См. [спецификацию 0011-device-creation-qr-permission-dark-theme](specs/0011-device-creation-qr-permission-dark-theme.md).

## Milestone 8 — Backlog (пост-MVP, не приоритизировано)

- [ ] Push-уведомления (FCM) в Viewer App
- [ ] Поиск по тексту сообщений, экспорт истории
- [ ] Web-версия просмотрщика
- [x] Локальная связка Android + backend для автотестов (не полагаться только на ручной E2E). Обнаружено при ручном тестировании Milestone 6/7 (2026-08-26): все существующие Android-тесты используют fake `ApiService`/моки, которые обходят реальную JSON-сериализацию и реальный HTTP-стек — из-за этого не были пойманы автотестами два реальных дефекта (`LoginRequest` сериализовался как `username` вместо ожидаемого бэкендом `login`; отсутствие `network_security_config` блокировало cleartext-трафик на debug-сборке к локальному бэкенду), и оба всплыли только при ручном прогоне на физическом устройстве. Закрыто спекой [0009-real-backend-integration-tests](specs/0009-real-backend-integration-tests.md): 4 инструментированных теста (login, добавление устройства по `download_token`, приём сообщения через webhook, realtime через SSE) против реального бэкенда в Docker, изолированные от обычного `connectedAndroidTest`. Открыто в backlog этой же спеки: CI-интеграция и настраиваемый base URL вместо захардкоженного `127.0.0.1:8080`.
- [ ] Раздельное управление несколькими SIM-слотами на одном устройстве
